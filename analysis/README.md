# Analysis workflows

This directory contains the analysis code and aggregate estimates used in the November 2026 manuscript (V15). The statistical routines retain the original estimators, adjustment variables, random seeds and sample definitions. Paths have been made relative to this directory, and the figure scripts omit panel headings, as in the current manuscript.

## Start with the aggregate data

The public CSV files contain estimates, confidence intervals, sample counts, scaling parameters and plotted distributions. They contain no player identifiers, match identifiers or raw match payloads. These files support inspection of the reported results and reconstruction of the figures.

From the repository root:

```bash
python -m pip install -r analysis/requirements.txt
python analysis/run.py --list
python analysis/run.py --stage figures --execute
```

Figures are written to `outputs/current_figures/main` and `outputs/current_figures/supplementary` in PNG, PDF and TIFF formats. A different location can be supplied with `--output-dir`. The reconstruction uses the exported aggregate estimates; it does not refit the statistical models. Python 3.14 was used for the analysis, with the package versions recorded in `requirements.txt`.

## Re-estimation with individual-level inputs

Raw Riot records and individual-level intermediate tables are not distributed here. Full model estimation requires those inputs, as described in `INPUTS.md`. The scripts open the source SQLite database in read-only mode. Supply its location through `RIS_DATABASE`; timeline and match-detail shard roots can be set through `RIS_TIMELINES` and `RIS_MATCH_DETAILS`.

Once the input tables are present, the current analysis order is:

1. Construct the baseline participant and sample tables with the scripts in `baseline/code/`.
2. Estimate the base peer models using `revision/code/peer/`, including the strict holdout and common discovery scaling.
3. Run `regional`, `role_pairs`, and then `regional_summaries`.
4. Run `cross_activity`.
5. Run `objective`, followed by `time_windows`.

The runner prints commands by default. Add `--execute` to estimate a selected stage, for example:

```bash
python analysis/run.py --stage time_windows
python analysis/run.py --stage time_windows --execute
```

Re-estimation writes analysis outputs to their documented table and cache directories. Use a separate checkout when comparing a new run with the distributed estimates. Intermediate covariance arrays and bootstrap draws are generated by the estimation stages and are not needed to redraw the public figures.

## Interpretation of the outputs

- The discovery sample contains 126,000 focal players and 2,240,354 unique matches. Player–match observations and directed player pairs are distinct analysis units.
- `holdout` denotes a player holdout from the same sampling pool. `strict` is a nested, more restrictive holdout. The two holdouts are not independent datasets.
- Propensities are estimated from other matches, excluding the target match; these are not necessarily earlier in calendar time.
- ORIV addresses measurement error in the split-half propensity measure. It does not randomize teammates or identify a causal peer effect.
- Role-pair, cross-activity, team-ratio and window analyses were developed after examining the initial results.
- Team placement is the sum of all five members' placement. The team-to-own ratio compares fitted slopes on the same focal player's propensity.
- Timeline outcomes concern the first eligible neutral objective after the cutoff, not the final winner. Window models adjust for the 10-minute state. Their estimates describe conditional associations.
- Region and sample labels must be read literally. In particular, use `keep_default_na=False` when reading CSV files so that the region label `NA` is retained.
- No TW records are used in these workflows.

## Provenance

`provenance.json` records SHA-256 hashes of the original source files and distributed files. Aggregate CSVs are copied byte-for-byte. Portability edits change file locations and figure heading presentation, without changing statistical calculations. `release_checks.json` records the checks performed for this release.
