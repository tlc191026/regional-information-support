# Individual-level inputs

The public figure workflow uses aggregate CSVs and runs without these inputs. The following files are required for full statistical re-estimation. They are listed relative to `analysis/`.

| Input | Purpose and required contents |
| --- | --- |
| `private/lol_data.db` or `RIS_DATABASE` | The source SQLite database containing the sampling roster, match metadata, participant records and timeline index. Table names and selected fields are specified in `baseline/code/db_extract.py`. |
| `timeline/data/canonical_focal_links.parquet` | Canonical focal player–match links, including `puuid`, complete `match_id`, roster region and tier. |
| `inputs/discovery/data/study0_canonical_participant_match_sample.pkl` | The frozen discovery participant–match sample, including rates and sampling fields. |
| `inputs/context/data/context_unresidualized_participant_scores.parquet` | Participant–match scores and identifiers used to build common-scale comparisons. |
| `inputs/context/data/canonical_unique_match_metadata.parquet` | Match metadata, including complete match identifier, game version, duration and roster-derived grouping variables. |
| `inputs/context/data/bootstrap_weights_primary_region_tier_1000.npy` | Fixed region-by-tier bootstrap weights. |
| `inputs/discovery/tables/study0_sampling_counts.csv` | Aggregate sampling-stratum counts. |
| `timeline/data/timeline_features_0_10.parquet` | Frame-aligned team maintenance, early state, eligibility and post-cutoff objective features. |
| `timeline/data/aligned/timeline_targets_all.parquet` | Indexed timeline payload locations with full match identifiers. |
| `timeline/data/aligned/timeline_source_file_inventory.json` | Payload shard inventory used by the parser. |
| `minute_timeline/data/minute_shards/` | Team-level minute counts used for reconciliation. |
| `baseline/data/` | Extracted participant records, discovery and holdout links, split-half tendency tables and participant minute features, generated by `baseline/code/` and `revision/code/peer/`. |
| `revision/data/peer/strict/` | Corrected strict-holdout pair and propensity inputs, generated by `revision/code/peer/build_strict.py`. |
| `revision/data/regional_performance/` | Match-level inputs with map-state proxies, generated by `revision/code/regional_performance/revise_performance.py`. |

Preserve complete server-prefixed match identifiers. The target samples and the propensity-estimation samples have separate eligibility rules; an integer match suffix alone is not a unique match identifier across servers. Region configuration and peer models use roster region. Time-window models restrict the actual match prefix to NA1, EUW1 and KR. The ten-minute objective model includes the small number of non-target-server records in the discovery roster sample, with an exclusion sensitivity reported separately.

All raw inputs remain outside version control. API credentials are neither required for the aggregate workflow nor stored in the analysis code. Any new data collection must follow the source platform's current access conditions.
